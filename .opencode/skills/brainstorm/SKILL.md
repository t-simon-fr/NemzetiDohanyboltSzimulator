Use when the user brings a game idea, feature wish, or "what if" before any plan or issue exists.

## Rules

1. Do not create or edit any repository file, and do not create or touch any GitHub issue until the user approves the brief.
2. Ask clarifying questions first (player-visible result, scope, non-goals). Prefer the `question` tool for decisions.
3. Draft the brief in chat, short:
   - Player-visible result (one paragraph, Hungarian)
   - Scope: what is in / what is out
   - Sketch of 3-6 acceptance criteria
   - Open risks or unknowns
4. Stop at the brief and ask for approval. Only after approval continue with `approved-design-to-issue`.
